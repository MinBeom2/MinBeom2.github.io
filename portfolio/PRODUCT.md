# 김민범 포트폴리오

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

백엔드·SI·소프트웨어 개발 채용 담당자와 기술 면접관. 프로젝트에서 본인이 맡은 범위와 실제 구현·검증 기록을 읽고 연락할 수 있는 포트폴리오다.

## Product Purpose

김민범의 구현 경험과 문제 해결 과정을 소개한다. 홈에서 대표 프로젝트와 역할을 빠르게 확인하고, 각 프로젝트의 상세 모달에서 판단·검증·근거를 읽는다. 모달을 닫으면 읽던 홈 위치로 돌아온다.

## Operating Context

React, TypeScript, Vite의 정적 웹 사이트. GitHub 사용자 사이트 MinBeom2.github.io에 배포할 계획이다. 실제 저장소는 C:\MinBeom2.github.io, 앱은 portfolio 하위 폴더에 있다. 상세는 홈 위의 native dialog로 표시한다. 기존 해시 주소의 직접 접근·새로고침도 모달로 지원한다.

## Capabilities and Constraints

- Ait와 ONEWORK는 SSAFY 6인 팀 프로젝트다. 팀 기능과 본인 담당을 구분한다.
- SteamFolder는 개인 프로젝트이며 외부 배포 전 로컬 개발 중이다.
- nGrinder 수치는 기록된 개발·검증 조건의 결과다.
- LIKE 검색 조건을 제외한 결과는 병목 진단 대조 실험이다.
- 좋아요 총 100건 요청을 32개 작업 스레드로 실행해 최종 100개를 확인한 작업은 종료 후 개인 브랜치다. 팀 배포 미반영이다.
- ONEWORK의 localhost 요청은 수정했으며 HTTPS 혼합 콘텐츠 통합 문제는 미해결이다.
- 수상 실적은 없다. 공개 데모와 Ait 캡처는 나중에 추가할 계획이다.
- 새로운 성과·기간·운영 지표·측정 조건은 질문과 근거 없이 작성하지 않는다.

## Brand Commitments

화면 문구와 메타 설명에 중간 점을 사용하지 않는다. 나열은 쉼표로, 문장 연결은 자연스러운 조사와 접속어로 표현한다.

사용자가 밝은 회색 바탕과 차콜 글자의 모던한 방향을 선택했다. 코드로 구현하고 실제 화면에서 검토한다. 실제 프로젝트 로고의 원래 색상을 임의로 바꾸지 않는다. 2026-10-14 사용자 요청에 따라 헤더는 이름·로고·연락 버튼을 제거하고 프로젝트·작업 방식·소개만 중앙의 어두운 아일랜드에 배치한다. 스크롤 위치에 따라 메뉴를 강조하고, 프로젝트 상세는 새 페이지 대신 모달로 연다.

2026-10-16 표시한 스크린샷에 따라 홈의 Ait 검증 카드, 프로젝트 살펴보기·GitHub 버튼, 주 사용 기술 목록과 소개의 GitHub 링크를 제거한다. 프로젝트 목록은 세 프로젝트 모두 같은 크기의 작은 정사각 타일에 로고·이름만 표시한다. 클릭하면 기존 상세 모달이 확대되어 열린다. SteamFolder의 제공된 로고가 없어 기존 아이콘 체계의 중립 폴더 아이콘으로 표시하며 공식 로고를 만들지 않는다.

후속 디자인 확인에서 사용자는 큰 소개 문구를 유지하되 소개와 프로젝트를 더 가깝게 배치하고, 홈·기술 목록·프로젝트 상세의 간격과 위계를 함께 정돈하는 방향을 선택했다. 기존 삭제 항목과 정사각 타일, 기술의 예시 등급·근거 펼침 방식은 유지한다.

이후 사용자는 첫 소개를 더 크게 보여주고 프로젝트가 첫 화면 아래로 내려가도록 요청했다. 데스크톱과 모바일 모두 첫 화면을 소개로 채우는 방향을 확인했으며, 이 요청이 앞선 소개 밀도 선택을 대체한다. 제목은 두 줄을 유지하고 프로젝트는 스크롤하거나 상단 메뉴로 이동해 확인한다.

## Product Principles

- 개인 기여와 팀의 전체 결과를 구분한다.
- 검증 조건과 현재 상태를 수치와 함께 읽을 수 있게 한다.
- 같은 긴 기록을 홈과 상세에 중복하지 않는다.
- 사실과 실제 자료를 우선하고 필요한 자료는 사용자에게 묻는다.
