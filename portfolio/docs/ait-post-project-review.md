# Ait 추가 검증 설명과 브랜치 확인

2026-10-22 사용자 요청에 따라 GitHub Ait의 브랜치 관계를 확인하고 포트폴리오 설명을 수정했다.

## 브랜치 이동 판단

사용자가 말한 DEV는 저장소에 있는 develop 브랜치로 확인했다. GitHub 원격 브랜치와 원본 저장소의 동일한 커밋을 대조했다.

| 브랜치 | 확인한 커밋 |
| --- | --- |
| minbeom/Improve | 62801e186928ce53a6df913baa4b422e72ffd8e2 |
| develop | 2c6a950494d6edba2c1733eec96978e76f23c335 |
| master | 712362839fba5634bb6e30bd272213912f3f576f |

develop에는 개인 개선 브랜치에 없는 `2c6a950`과 `2574ff2` 두 커밋이 있다. master도 개인 개선 브랜치의 조상이 아니다. 두 대상 모두 `git merge-base --is-ancestor` 결과가 1이어서 fast-forward로 옮길 수 없다.

사용자가 이동할 수 없으면 내용만 고치라고 지정했으므로 브랜치 변경과 push는 진행하지 않았다. GitHub와 원본 프로젝트의 이력은 변경하지 않았다.

## 설명 범위

- ‘조회 성능과 데이터 정합성 검증’에서는 nGrinder 응답 시간 비교, 종료 후 좋아요 수 갱신 유실 방지와 통합 테스트 결과를 설명한다.
- 테스트 조건은 요청 100건과 작업 스레드 32개다. 100명이 완전히 동시에 요청한 테스트로 표현하지 않는다.
- 개인 브랜치와 팀 배포 미반영 안내는 문제 해결의 주석에 모은다. 결과에는 종료 후 추가 검증이며 팀 배포본에 반영하지 않았음을 남긴다.
- 좋아요 수 갱신과 통합 테스트 근거는 GitHub의 [2adfa5d 커밋](https://github.com/MinBeom2/Ait/commit/2adfa5d5d2717a6a8289162da04f4e5da4dd50ae)으로 연결한다.
- 락 적용 전후 처리량이나 응답 시간 향상을 새로 주장하지 않는다.

## 윤문과 검증

확인한 사실로 작성한 수정 초안을 humanize-korean으로 다듬는다. 원래 화면 문구와 사실 초안은 `_workspace/2026-10-22-005-86fc`에 따로 보존했다. 윤문 변경률은 기존 화면과 수정 문구의 차이가 아니라 사실 초안과 최종 윤문본 사이의 차이다.

독립 monolith 역할의 light 경로에서 추가 수정할 패턴이 없어 사실 초안을 보존했다. 공통 게이트 exit 0, 변경률 0%, 등급 B, 자체검증 6/6이다. 별도 진단과 finalizer는 light 경로에서 승급 조건이 없어 실행하지 않았다. 남은 경고는 없다.

TypeScript 검사와 Vite 프로덕션 빌드, `git diff --check`를 통과했다. 원본 통합 테스트에서 `newFixedThreadPool(32)`, 요청 작업 100건과 최종 `likeCount` 100 검증을 대조했다. Ait 서버의 통합 테스트 자체를 이번 작업에서 다시 실행한 것은 아니다.
