# Design System: 김민범 포트폴리오

2026-10-20 프로젝트 상세 목차: 세 프로젝트의 상세 창 내부에서 읽는 위치를 추적해 현재 항목 하나에 `aria-current="location"`을 표시한다. 기존의 옅은 회색 배경과 차콜 650 굵기를 사용한다. 읽기 기준선은 상세 스크롤 영역 상단에서 높이의 25%와 120px 중 작은 값이며, 마지막까지 내리면 ‘코드와 근거’를 표시한다. 스크롤 이벤트는 프레임당 한 번 측정하고 상세 내용 및 창 크기의 변화도 관찰한다. 따라서 목차 클릭, 세부 기록 직접 진입, 펼침 내용의 높이 변경과 화면 크기 전환에 맞춰진다. 스크롤을 따라 주소나 초점을 갱신하지 않는다. 작은 화면의 목차는 상단 두 열을 유지하고 링크의 가로 안쪽 여백을 상태와 관계없이 10px로 고정해 강조 시 글자가 밀리지 않게 한다.

상세 목차 검증: Ait 7개, ONEWORK 6개, SteamFolder 7개의 목차를 모두 눌러 각 본문과 현재 표시 하나가 일치하는 것을 확인했다. 직접 휠을 내려 담당 구현으로 이동하고 다시 올릴 때 문제와 목표로 돌아오는 표시, 문서 끝의 마지막 항목, Ait 동시성 세부 기록의 상위 ‘문제 해결’ 표시도 확인했다. 320px 화면의 모든 목차 링크는 높이 44px이며 가로 넘침이 없고 Enter로 항목을 이동할 수 있다. 960px에서 기술 선택 내용을 펼치고 닫을 때도 표시가 유지되며 1440px PC 배치로 전환할 수 있다. TypeScript와 Vite 빌드 및 layout 검사 통과. 증빙은 `.impeccable/review/project-contents/`에 저장한다.

2026-10-20 협업 경험 추가: 작업 방식의 협업 행은 사용자에게 확인한 스크럼 마스터 역할, 매주 KPT 회고 진행과 번다운 차트 점검을 먼저 설명한다. 기존 Git 작업 가이드는 두 번째 문단과 코드 및 근거 링크로 유지한다. 오른쪽의 역할, 주간 회고와 진행 점검은 기존 동시성 검증 목록과 공유하는 `.approach-facts` 정의 목록이며, 가이드까지 28px 간격을 둔다. 전체 두 행 구성과 회색 및 차콜, 기존 글꼴을 유지한다. 회고의 구체적인 개선 성과와 적용 프로젝트, 운영 기간 및 차트 수치는 임의로 추가하지 않는다. 같은 사실을 Notion 포트폴리오의 협업 요약과 협업 방식에 반영했다.

협업 경험 검증: 1440, 960, 390, 320px 화면에서 제목과 본문, 정의 목록 및 기존 코드의 가로 넘침이 없었다. 협업 가이드 링크를 Enter로 열고 Escape로 닫은 뒤 원래 링크로 초점이 돌아오는 것을 확인했다. TypeScript와 Vite 빌드 및 layout 검사 통과, 별도 마감 검토 ship이다. humanize-korean light 경로에서 연결어미 뒤 쉼표 한 곳을 제거했고 공통 게이트 변경률은 0.35%, 등급 B와 자체검증 6/6이다. 경고가 없어 finalize는 필요하지 않았다. 원문과 윤문본은 루트 `_workspace/2026-10-20-001-d2be/`에 보존하고, 생성된 작업 자료는 Git 추적에서 제외한다. 화면과 측정은 `.impeccable/review/scrum-collaboration/`에 있다.

2026-10-19 작업 방식과 도식 최신 규칙: 현재 작업 방식은 테스트와 검증, 협업 두 행이다. 가운데의 피드백 개선 항목은 실제 배포와 사용자 피드백 경험 이후 추가하며 현재 빈칸이나 예정 문구를 두지 않는다. 첫 행은 nGrinder 응답 시간과 조건, 좋아요 요청 100건과 32개 작업 스레드 및 최종 100개 검증을 묶는다. 동시성 결과는 프로젝트 종료 후 개인 개선이며 팀 배포 미반영임을 같은 묶음에 표시한다. 이 결정은 아래 이전의 작업 방식 세 행 설명보다 우선한다.

사용자 확인을 거쳐 도식의 화살표와 연결선을 제거했다. 실제 순서가 있는 피드백 저장과 분류, 직접 풀이와 리뷰 및 기록, 영상 전달은 공유 ProcessSteps를 사용한다. 24px 번호 열과 12px 간격, 단계 사이 16px, 제목 16px와 설명 14px로 구성하며 고정 높이를 두지 않는다. P0와 P1, P2는 순서가 아닌 조건별 알림 결과로 나란히 둔다. 복습 일정은 풀이 완료일 기준 1일, 3일, 7일 값을 선 없이 표시한다. Ait은 기능별 역할 정의 목록이며 모바일에서 역할과 설명을 위아래로 쌓는다. SteamFolder 폴더는 중첩 목록의 들여쓰기로 계층을 보존한다. 성능 표는 대상 열과 응답 시간 전후 및 TPS 전후의 5개 열을 사용하며 기존 수치와 자체 스크롤을 유지한다. 일반 링크 장식 화살표는 제거하고 펼침 및 새 탭 아이콘은 16px로 통일한다. 이 규칙이 아래 이전 화살표 도식 설명보다 우선한다.

작업 방식과 도식 정리 검증: 홈은 1440, 821, 820, 390, 320px 화면에서 두 작업 방식과 처리 단계, 조건별 알림, 복습 일정을 확인했다. 세 프로젝트의 기술 설명은 1440px과 320px에서 가로 넘침 없이 표시되고, 좁은 화면의 성능 표는 표 내부에서만 가로 스크롤된다. 수치와 측정 조건, 개인 개선의 팀 배포 미반영, ONEWORK의 HTTPS 미해결 상태를 보존했다. 성능 및 동시성 기록의 직접 진입, 닫은 뒤 링크로 초점 복귀, AI와 기술 및 스킬의 Enter와 Space 펼침을 확인했다. TypeScript와 Vite 빌드, layout 검사와 git diff --check를 통과했다. 별도 마감 검토에서 남은 두 기술 펼침 아이콘도 공유 16px 아이콘으로 수정했고 최종 판정은 ship이다. 화면과 측정 기록은 `.impeccable/review/process-cleanup/`에 있다.

## Overview

**Creative North Star: "밝은 회색, 차콜, 실제 기록"**

사용자가 확정한 밝은 회색 바탕과 차콜 글자를 구현한 현재 디자인 체계다. 넓은 여백, 왼쪽 정렬, 제한된 읽기 폭으로 프로젝트의 담당 범위와 검증 기록을 읽게 한다. 회색 농도가 제목·본문·조건·구획의 위계를 만들고, 원본 사진과 프로젝트 로고·실제 화면은 고유 색을 유지한다.

기존 홈의 순서와 두 글꼴의 역할을 유지한 refinement에서 추출했다. 프로젝트 상세도 같은 표면·글자·간격 체계를 사용한다. 이 문서의 토큰은 `src/styles.css`와 뒤에 적용되는 `src/case-studies.css`, 글꼴 로딩은 `src/main.tsx`, 구성과 상호작용은 `src/App.tsx`에 근거한다. 자산의 원본과 사용 경위는 `docs/assets.md`, 사실·기여·검증의 경계는 `PRODUCT.md`를 따른다.

**Key Characteristics:**

- 밝은 회색 바탕, 차콜 글자, 흰색 또는 옅은 회색 표면.
- 한국어의 읽기 위계와 영문 프로젝트명·수치의 글꼴 역할 분리.
- 본문은 표면 농도와 얇은 경계로 나누고, 아일랜드 헤더·상세 모달은 떠 있는 역할에만 그림자를 사용한다.
- 원본 사진·로고·실제 화면과, 개념도·흐름도로 명시한 자료.

## Colors

색은 사이트의 회색 위계와 원본 자산의 색으로 구성한다. 정확한 값은 위 frontmatter가 기준이다.

### Primary

- **차콜 (`ink`)**: 제목, 기본 본문, 주요 행동의 배경, 선택한 검증 사례, 도형 강조에 사용한다.
- **부드러운 차콜 (`ink-hover`)**: 주요 버튼의 hover와 기술 태그·상태 글자에 사용한다.

### Neutral

- **밝은 회색 (`surface`)**: 페이지와 모달의 기본 바탕. 중앙 헤더는 차콜 바탕을 쓴다.
- **흰 종이 (`paper`)**: 측정 기록, 실제 화면 주변, 프로젝트 내부 노드와 개인 프로젝트 본문 표면.
- **옅은 회색 (`pale`)**: 작업 방식 영역, 선택 버튼의 바깥 표면, 보조 행동의 hover.
- **본문 회색 (`muted`)**: 설명, 기술 적용, 검증 조건과 보조 링크.
- **조건 회색 (`quiet`)**: 작은 조건·기간·주석. 중요 내용도 읽을 수 있는 글자 대비를 유지한다.
- **구획선 (`line`)**: 모달 닫기 도구줄, 목록, 표, 상세 기록의 1px 경계.
- **행동 경계 (`control-line`)**: 보조 버튼, 연락 버튼, 아이콘 버튼의 경계.
- **반전 글자 (`inverse`, `inverse-muted`)**: 차콜 연락 영역과 어두운 영상 흐름도의 글자.
- **도식 회색 (`diagram-surface`)**: Ait 기능 흐름도, SteamFolder 개념도, 영상 중계 노드.
- **태그 회색 (`tag-surface`)**: 기술 태그와 개발 상태 배경.
- **영상 차콜 (`media-surface`)**: ONEWORK 영상 전달 구조의 어두운 배경.

**The Gray Hierarchy Rule.** 사이트의 구획과 행동은 회색 농도로 구분한다. 원본 프로젝트 로고·사진·서비스 화면의 색은 유지한다.

사이드카의 tonalRamp는 회색 색상표를 보여주기 위한 파생 미리보기다. 실제 구현에 새 색상 토큰을 추가하는 근거로 사용하지 않는다.

## Typography

**Display Font:** Noto Sans KR Variable, sans-serif.
**Body Font:** Noto Sans KR Variable, sans-serif.
**Project / Numeric Font:** Manrope Variable, Noto Sans KR Variable, sans-serif.

한국어 제목은 두께와 크기로 위계를 만든다. 영문 프로젝트명, 기술 목록, 기간·수치에는 Manrope를 사용한다. 두 Variable 글꼴은 npm 패키지에서 import하여 빌드에 포함한다.

### Hierarchy

- **Display:** 홈 제목은 두 개의 block span으로 두 줄을 유지한다. frontmatter의 유동 크기와 균형 줄바꿈을 사용하며 한국어 단어를 유지한다. 600px 이하에서는 `clamp(32px, 9vw, 46px)`와 줄높이 1.45, 360px 이하에서는 27px가 적용된다.
- **Intro Supporting Copy:** 첫 소개의 이름·역할은 20px·600, 설명은 20px·줄높이 1.9다. 600px 이하에서는 모두 16px로 줄인다.
- **Project Display:** 상세 프로젝트명. 820px 이하 44px이며 모바일 모달에서는 30px로 줄인다.
- **Headline:** 홈 영역 제목. 820px 이하 29px, 600px 이하 26px.
- **Detail Headline:** 상세 기록의 영역 제목. 후순위 상세 stylesheet가 데스크톱 25px, 600px 이하 22px를 적용한다.

Frontmatter는 대표 역할을 담는다. 기존 CSS의 반응형 제목·도식·메타 글자에는 15·17·19·22px 등 서술한 개별 크기와 중립 회색 변형이 남아 있다. 정적 검사에서 대표 토큰 범위 밖으로 표시되는 이 값들은 기존 읽기 위계를 보존한 의도적 변형이며, 새로운 헤더의 모바일 13px와 모달 배경·닫기 hover는 frontmatter에 추가했다.

## Elevation & Depth

본문의 깊이는 흰 표면, 옅은 회색 영역, 1px 경계와 여백으로 구분한다. 떠 있는 아일랜드 헤더에는 `0 12px 28px rgba(0, 0, 0, .14)`, 모달에는 `0 24px 72px rgba(0, 0, 0, .24)` 그림자를 사용한다. 모달 배경은 `rgba(0, 0, 0, .46)`로 어둡게 한다. 기능 도식의 내부 노드는 흰색, 영상 흐름도는 어두운 차콜 위의 반전 글자를 사용한다.

**The Flat Surface Rule.** 본문의 구분은 농도·경계·간격으로 표현한다. 그림자는 떠 있는 헤더와 모달에 한정하며 정보 카드마다 반복하지 않는다.

## Shapes

아일랜드와 선택 표시는 999px 캡슐 모서리, 상세 모달은 16px 모서리이며 모바일에서는 14px다. 주요 표면은 14px 모서리, 모바일 검증·프로젝트 표면은 12px 모서리다. 버튼과 메뉴 제어는 8px, 기술 태그·개발 상태는 4px, 목차 항목은 6px다. 실제 화면의 모서리는 10px, 인물 사진은 12px다. 도식 노드에는 12px 모서리를 사용한다.

원본 로고는 object-fit: contain으로 비율을 보존한다. 홈의 기본 로고 영역은 112×64px, Ait 로고는 64×64px, ONEWORK 폭은 112px다. 1500px 이상에서는 영역 128×80px, 로고 80×80px와 ONEWORK 폭 128px를 쓴다. 820px 이하 영역은 80px 폭, 600px 이하에서는 영역 60×48px, 로고 48×48px와 ONEWORK 폭 60px다. 홈 사진은 width: 100%, height: auto와 object-fit: contain으로 전체를 표시한다. 고정 프레임 높이, 최대 높이와 별도 종횡비를 두지 않으며 원본 비율대로 자연 높이를 사용한다. 프로젝트가 공통 너비로 늘어나도 사진의 선호 폭은 PC 약 566.67px, 820px 이하 606px로 유지하며 더 좁은 화면에서만 줄어든다. 원본 이미지 파일은 보존한다. 상세 로고는 64px, 모바일 모달에서는 44px다. ONEWORK 상세의 실제 화면과 인물 사진도 비율을 유지한다. SteamFolder 타일의 폴더 아이콘은 중립 식별 표시이며, 상세의 폴더 형태와 Ait 연결선은 기능 설명 도식이다.

작업 방식은 제목 24px, 본문 18px와 줄높이 1.85, 코드 및 측정 조건 14px를 쓴다. 수치에는 Manrope 36px와 tabular numerals를 적용한다. 모바일은 제목 22px와 본문 16px, 수치 32px이며 360px 이하에서는 수치 28px와 다음 줄 단위로 좁은 폭을 맞춘다. AI 제목은 28px에서 모바일 24px, 사례 제목은 24px에서 모바일 22px다. 도식 단계는 16px, 보조 설명은 14px이며 펼침 본문은 16px다.

## Components

### Buttons

차콜 채움의 주요 버튼, 경계가 있는 투명 보조 버튼, 밑줄이 나타나는 텍스트 링크를 사용한다. 기본 버튼은 14px·600, 최소 높이 48px, padding 11px 20px, 8px 모서리다. 모바일은 13px, 최소 높이 46px, padding 10px 15px다. 텍스트 링크와 메뉴 항목은 최소 높이 44px다.

주요 버튼 hover는 `ink-hover`, 보조 버튼 hover는 `pale`다. 링크 hover는 밑줄로 표시한다. `:focus-visible`은 기본 2px 차콜 outline·5px offset이며 주요 버튼은 4px offset, 어두운 연락 영역에서는 흰 outline을 사용한다. 비활성 제어는 opacity .55와 not-allowed cursor를 사용한다.

### Chips

기술 목록과 개발 상태는 작은 회색 표면, 4px 모서리, 12px 글자, padding 4px 9px를 사용한다. 기술 태그는 설명용 목록이며 클릭 상태를 만들지 않는다.

### Cards / Containers

홈 프로젝트는 개요와 사진을 감싼 하나의 흰 표면, 1px 경계와 14px 모서리로 구성한다. 내부 영역에는 별도 테두리나 모서리를 두지 않는다. 외곽 카드 padding은 12px 16px, 기본 내부 간격은 16px다. space-evenly로 남는 폭을 세 공간에 고르게 나누므로 실제 좌우 및 가운데 간격은 PC 화면에 따라 커진다. 개요의 추가 padding은 세로 4px뿐이며 로고와 글의 간격은 16px, 이름과 개요 사이 간격은 8px다. 820px 이하에서는 카드 padding을 사방 16px로 맞추고 개요 padding은 제거한다. 단일 grid 열은 minmax(0, 606px)로 제한하고 가운데 정렬해 기존 내용 크기를 보존한다. 로고와 개요를 80px 열과 나머지 열에 왼쪽 정렬하고 사진을 아래에 둔다. 600px 이하에서는 60px 로고 옆에 이름을 두고 개요는 그 다음 전체 폭에 배치한다. 모바일 개요의 간격은 12px, 외곽 모서리는 12px다. hover는 전체 카드의 경계색, 키보드 focus는 전체 카드의 기존 outline으로 표현한다.

사진 영역은 개요와 같은 상세 링크 안에 있으며 원본 파일을 별도로 여는 링크와 하단 캡션은 제거했다. 사진 영역 자체의 padding은 없고 공통 card padding과 space-evenly 배분으로 왼쪽 개요 기준선과 사진 오른쪽 기준선의 여백을 동일하게 맞춘다. 1440px에서는 좌우와 가운데가 약 52.67px, 1920px에서는 106px, 2560px에서는 132.67px다. 사진은 width 100%와 height auto 및 contain으로 가로 폭에 맞춰 전체를 표시하고 프레임에 따른 잘림이나 여백을 만들지 않는다. 개요, 사진과 카드의 여백 어디를 눌러도 같은 프로젝트 상세 모달이 열린다.

상세의 주석 callout은 실제 구현의 옅은 회색 배경, 10px 모서리, padding 22px 24px를 사용한다. 검증·기술·근거 목록은 1px 경계로 나누며 별도 카드로 감싸지 않는다.

### Skills Disclosure

제목과 숙련도 기준은 두 열 grid에 두고 안내 문장을 그 아래 전체 폭으로 배치한다. 예시 등급 안내와 모두 펼치기·접기 버튼은 같은 도구줄에 둔다. 분류 버튼은 13px, 개수는 12px이며 선택 상태는 차콜 채움이다. 기술 행은 원본 SVG 또는 텍스트 약칭·기술명·대표 근거·예시 등급을 보여준다. 대표 근거는 데스크톱 13px·모바일 12px, 펼친 경험은 14px·줄높이 1.9다. 행별 disclosure와 분류별 모두 펼치기, 기존 프로젝트 상세 연결을 유지한다. 이 크기는 기술 영역의 역할별 값이며 전역 최소 글자 크기를 새로 정의하지 않는다.

### Navigation

헤더는 이름·브랜드 마크·연락 버튼 없이 프로젝트·작업 방식·소개만 담는 중앙 아일랜드다. 캡슐은 차콜 바탕, 348×60px, padding 6px, 999px 모서리이고 상단 16px에 붙는다. 600px 이하에서는 310×56px·상단 12px이며 작은 화면은 좌우 20px 여백 안에 줄어든다. 세 링크를 항상 가로로 보여주며 최소 높이는 48px, 모바일 44px다.

스크롤과 메뉴 선택으로 현재 읽는 섹션을 추적한다. 선택한 메뉴는 밝은 이동 표면, 차콜 글자와 `aria-current="location"`을 사용한다. 첫 소개 화면에서 해당 섹션에 도착하기 전에는 선택 표시를 숨긴다. 모달이 열리면 프로젝트 메뉴를 선택 상태로 유지한다. 키보드 focus는 반전 outline으로 드러낸다.

상세에는 breadcrumb, 목차, 전체 프로젝트 복귀, 다음 프로젝트 링크가 있다. 목차 hover는 옅은 회색 배경이다. 상세 목차의 활성 위치 추적은 구현되지 않았다.

960px 이하 목차는 본문 앞 두 열로 배치하며 모바일에서도 링크 최소 높이 44px를 유지한다.

### Project Modal

native `dialog.showModal()`로 프로젝트 상세를 열어 배경을 inert 상태로 만들고 키보드 초점을 모달에 둔다. 배경 스크롤을 고정하고 닫기 도구줄을 항상 보이게 유지한다. Escape·닫기 버튼·모달 바깥 클릭·뒤로 가기로 닫으면 이전 스크롤과 진입 링크의 초점을 복원한다. 상세 목차와 다른 프로젝트 선택은 현재 모달 안에서 동작한다. 새로운 독립 페이지를 렌더링하지 않는다.
모달은 열릴 때 `scale(.94)`·opacity .6에서 원래 크기·opacity 1로 220ms 확대한다. easing은 `cubic-bezier(.16, 1, .3, 1)`이며 reduced motion에서는 animation을 끈다.

모달 breadcrumb의 상단 여백은 16px, 헤더는 위 16px·아래 28px다. 모바일은 각각 12px와 위 12px·아래 24px이며 프로젝트명 30px·로고 44px·부제 18px로 첫 화면을 압축한다. 기간·구성·담당 역할은 데스크톱 세 열, 모바일 두 열에서 역할만 전체 폭으로 두며 모바일 label은 12px·값은 13px다.

## Do's and Don'ts

### Do:

- **Do** 회색 농도와 글자 크기·두께·간격으로 정보의 위계를 유지한다.
- **Do** 원본 사진·로고·실제 화면의 색과 비율을 유지하고 출처와 사용 경위를 기록한다.
- **Do** 도식에는 흐름도·개념도라는 설명을 붙이고 실제 화면과 구분한다.
- **Do** 작은 화면에서는 열을 순서대로 접고, 측정 표의 가로 스크롤은 표 안에 한정한다.
- **Do** 수치와 검증 조건, 본인 기여와 현재 상태를 가까이 배치하여 함께 읽게 한다.

### Don't:

- **Don't** 사이트 행동에 이전 파랑 강조 체계를 다시 적용하거나 원본 자산의 색을 회색으로 변환한다.
- **Don't** 프로젝트마다 같은 외곽선과 그림자를 반복하여 기록보다 컨테이너를 강조한다.
- **Don't** 제공되지 않은 서비스 화면·로고·데모를 만들어 실제 자료로 제시한다.
- **Don't** 팀의 전체 화면이나 측정 기록을 개인의 운영 성과·해결 완료로 표현한다.


## 2026-10-17 승인한 소개와 프로젝트 비중 조정

최신 사용자 승인은 풀스크린 소개를 유지하면서 큰 화면 제목을 최대 96px로 확대하고, 프로젝트 제목 아래에 기존 작은 정사각 타일 세 개를 배치하는 방향이다. 이 결정이 앞선 80px 최대 제목과 프로젝트 좌우 배치 설명을 대체한다.

색과 글꼴은 기존 Noto Sans KR, Manrope와 회색 여섯 역할을 유지한다. 소개 제목은 clamp(48px, 7.2vw, 96px), 줄높이 1.3이며, 이름 위 간격은 32px다. 모바일의 두 줄 제목 크기와 전체 화면 소개, 아일랜드 메뉴, 원본 로고와 프로젝트 모달은 보존한다.

프로젝트는 단일 열, 제목과 타일 사이 40px, 최소 높이 480px, 위 80px·아래 96px 여백으로 구성한다. 작은 타일은 기존 184px와 좁은 화면의 크기 규칙을 유지한다. 820px 이하에서는 고정 최소 높이를 해제하고 위 64px·아래 72px, 600px 이하에서는 위 56px·아래 64px로 줄인다.

작업 방식은 상하 80px·88px, 최소 높이 600px를 기준으로 실제 내용이 늘어나면 자연스럽게 커진다. 세 열에 원칙, 구현 사례, 실제 근거, 관련 상세 링크를 순서대로 둔다. 근거는 채팅 조회 평균 응답의 전후 값과 개인 검증 조건, JWT와 멤버 확인 흐름, 공유한 Git 가이드의 작업 시작 예시다. 별도 장식 카드나 임의 성과를 추가하지 않는다.

960px 이하에서는 작업 방식을 한 열로 풀고 최소 높이를 해제한다. 항목 사이 간격과 얇은 가로선으로 구분하며 링크 높이는 44px 이상 유지한다. 상세 근거 링크를 열면 대상 제목에 초점을 옮기고 닫으면 진입 링크로 복귀한다.

320px 화면에서는 stable scrollbar gutter와 충돌하던 body 최소 폭을 제거한다. 360px 이하 측정값은 23px로 줄여 단위를 포함한 숫자가 열 안에 들어가게 한다. 실제 확인과 도구 제한은 [검증 기록](layout-verification-2026-10-17.md)에 남긴다.


## 2026-10-17 프로젝트 전체 폭과 개요

후속 사용자 요청에 따라 프로젝트 행은 고정 184px 타일에서 전체 콘텐츠 폭의 동일한 3열로 바뀐다. 기존 회색·차콜 팔레트와 Noto Sans KR, Manrope, 원본 로고를 유지한다. 카드 너비는 남은 폭을 균등하게 나누고, 최소 높이는 300px, 간격은 24px다. 화면이 1100px 이하이면 간격은 20px이며 700px 이하에서는 한 열, 최소 높이 260px로 바뀐다. 600px 이하의 간격은 16px다.

각 카드의 순서는 로고, 프로젝트 이름, 한 문장의 서비스 개요다. 중앙 정렬을 유지하고, 개요는 15px, 줄높이 1.8, 최대 30ch로 읽기 쉽게 제한한다. 전체 카드가 상세 모달 진입 링크이며 개요를 aria-describedby로 연결한다. 상세 내용의 긴 설명을 복제하거나 성과를 새로 주장하지 않는다. 이 결정이 앞선 작은 정사각 타일과 모바일 2열 규칙을 대체한다.

```text
프로젝트
[       Ait       ] [     ONEWORK     ] [   SteamFolder   ]
[ 면접 준비 개요  ] [ 설비 관제 개요  ] [ 게임 정리 개요  ]
```

콘텐츠 폭은 세 카드가 모두 채우고, 다음 작업 방식 영역과의 정렬을 맞춘다. 카드에 또 다른 테두리 패널이나 장식 라벨은 추가하지 않는다.


### 프로젝트 미리보기 검증

프로덕션 빌드와 1440, 1024, 701, 700, 390, 320px 브라우저 확인을 마쳤다. 1440px에서 콘텐츠 폭은 1120px, 카드 너비는 각각 약 357.33px, 높이는 300px이며 세 카드가 행을 모두 채운다. 설명 줄 수와 무관하게 데스크톱의 로고·이름 시작 높이를 맞췄다. 701px에서도 세 열과 같은 제목 높이를 유지하고, 700px 이하에는 한 열로 전환한다. 최종 확인에서 페이지와 카드 내부의 가로 넘침이 없었다.

세 프로젝트 링크의 올바른 모달 열기와 닫기, 진입 링크로의 초점 복귀를 확인했다. 개요는 각 링크의 aria-describedby 대상과 연결된다. 로드가 끝난 프로젝트 이미지 실패나 확인한 브라우저의 콘솔 오류·경고는 없었다. 새 래스터 자산을 추가하지 않았으며 기존 자산의 색과 비율을 유지한다. Impeccable 엔진은 앞선 실행에서 사용할 수 없음을 확인했으므로 이번 검증은 빌드와 실제 브라우저, 소스 점검으로 수행했다. 판정: 요청한 전체 폭 배치와 간단한 개요를 충족하며 배포 가능하다.


## 2026-10-17 첫 소개 높이 축소

사용자 후속 요청에 따라 소개의 100svh 최소 높이를 제거했다. 섹션은 내용 높이와 위 64px, 아래 72px 여백으로 구성한다. 제목은 clamp(44px, 6vw, 80px), 기존 줄높이 1.3과 두 줄 문구를 유지한다. 제목 비중과 상하 여백을 함께 줄여 프로젝트가 더 일찍 이어지도록 한다. 600px 이하에는 위 40px, 아래 56px 여백을 적용하고 기존 모바일 제목 크기를 유지한다. 높이는 고정하지 않아 글자가 늘어나면 자연스럽게 확장된다. 앞선 전체 화면 소개와 최대 96px 제목 규칙은 이 결정으로 대체된다.

검증: 프로덕션 빌드 통과. 1440×900과 1366×768에서 소개 높이는 약 546px, 프로젝트 시작은 페이지 상단에서 약 626px다. 1024×768에서는 소개 약 495px, 390×844에서는 약 358px, 320×740에서는 약 338px였다. 모든 확인 크기에서 프로젝트 제목이 첫 화면 안에 들어오고 소개의 두 줄 제목, 가로 넘침 없는 배치를 유지했다. 확인한 브라우저의 콘솔 오류와 경고는 없었다. 높이를 고정하거나 새 모션·자산을 추가하지 않았다. 판정: 요청한 소개 크기 축소를 충족한다.
