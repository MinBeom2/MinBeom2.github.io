# 2026-10-17 소개와 프로젝트 영역 비중 조정

## 승인한 방향과 결과

첫 소개의 전체 화면 높이와 두 줄 제목, 기존 회색과 차콜, 작은 정사각 프로젝트 타일을 유지했다. 큰 화면에서는 제목을 최대 96px로 키웠다. 프로젝트 제목과 타일을 위아래로 배치하고, 작업 방식에 실제 근거와 상세 기록 링크를 추가했다.

1440×1000에서 프로젝트는 약 486px, 작업 방식은 약 635px다. 고정 height 대신 min-height를 사용해 텍스트가 늘어나면 섹션도 커진다. 프로젝트는 820px 이하, 작업 방식은 960px 이하에서 최소 높이를 해제한다.

## 디자인 판단

- 팔레트: 바탕 #f4f4f4, 글자 #262626, 타일 #ffffff, 작업 방식 #ebebeb, 보조 글자 #595959, 구분선 #d5d5d5.
- 글꼴: 기존 Noto Sans KR 본문과 제목, Manrope 영문과 측정값. 실제 Git 명령어에만 monospace를 사용한다.
- 정렬: 기존 콘텐츠 폭 1120px와 왼쪽 정렬을 유지한다. 소개의 큰 글자가 중심을 잡고, 프로젝트와 작업 기록이 뒤를 잇는다.
- 별도 장식 카드나 섹션 번호를 추가하지 않았다. 근거의 내용에 맞춰 수치 비교, 권한 확인 순서, 실제 명령어를 각각 표현했다.

```text
두 줄 소개, 이름, 설명
프로젝트 제목
[ Ait ] [ ONEWORK ] [ SteamFolder ]
작업 방식 제목
원칙               원칙               원칙
측정값과 조건      권한 확인 순서      Git 가이드 예시
상세 기록 링크     상세 기록 링크      상세 기록 링크
```

독립 소스 검토에서 나온 최소 높이 사용, DOM 읽기 순서 보존, 중간 폭 대응, 상세 링크의 초점 이동을 반영했다.

## 근거의 범위

- 채팅 조회 평균 응답 1,804.71ms → 131.59ms와 개인 검증 환경, Vuser 50, 1분 조건을 함께 표시한다. 기존 측정 기록과 코드 조사에 근거하며 운영 성능으로 확장하지 않는다.
- 채팅은 연결할 때 JWT 검증, 전송 전 그룹 멤버 확인, 저장 후 그룹에 발행하는 구현 순서를 요약한다.
- Git 명령어는 Ait의 docs/Git_command.md에 공유된 브랜치 작업 시작 예시다. 새 기능 브랜치 이름은 예시다.
- 새로운 이미지나 로고는 만들지 않았다. 기존 원본 자산의 색과 비율을 유지한다.

## 확인

- TypeScript와 Vite 프로덕션 빌드 통과.
- 2560, 1440, 1100, 961, 960, 900, 820, 600, 390, 320px 폭을 실제 브라우저에서 확인했다.
- 데스크톱은 3열 근거, 좁은 화면은 1열 순서로 읽힌다. 프로젝트는 큰 화면 3개, 모바일 2열 타일을 유지한다.
- 320px의 scrollbar-gutter와 body 최소 폭 충돌을 해소했다. 360px 이하 측정값을 23px로 보정했다. 최종 320px에서 페이지와 근거 내부 가로 넘침이 없다.
- 소개 제목은 좁은 화면에서도 지정한 두 줄을 유지한다. 근거 링크의 높이는 최소 44px다.
- 세 근거 링크가 해당 모달 제목에 초점을 옮긴다. Escape로 닫으면 진입 링크와 홈의 읽던 위치로 돌아온다. 모바일의 긴 측정 표는 표 영역 안에서 가로 스크롤된다.
- 320px 모달 스크롤 영역의 scrollWidth와 clientWidth는 모두 274px였다.
- 작업 방식 본문 대비 5.88:1, 보조 설명 4.96:1, 링크 12.69:1을 실제 계산 스타일로 확인했다.
- 확인한 로컬 브라우저에서 콘솔 오류와 경고, 로드가 끝난 이미지의 실패가 없었다.
- 기존 reduced-motion 규칙과 키보드 focus-visible 처리는 소스에서 보존했다. 별도 운영체제 모션 설정이나 브라우저 확대 모드는 변경하지 않았다.

## 검사 도구와 판정

Impeccable context와 layout detector는 engine 0.1.11이 없고 캐시 디렉터리를 만들 수 없어 실행되지 않았다. 자동 검사 통과로 기록하지 않는다. 기존 PRODUCT.md, docs/design.md와 실제 소스, 렌더링, 계산 스타일, 키보드 동작을 직접 확인했다.

판정: 승인한 레이아웃 범위에서 배포 가능. 추가 장식이나 범위 밖의 콘텐츠 개편 없이 검증을 마쳤다.
