# 프로젝트 소개 개편 (2026-10-22)

## 구성과 범위

사용자가 프로젝트 전체 기준의 소개를 승인했다. 세 프로젝트의 첫 항목을 ‘프로젝트 소개’로 바꾸고 목표, 배경, 주요 기능 순서로 읽도록 구성했다. 서비스 기능은 네 개씩 보여 주고 개인 기여는 다음 ‘담당 구현’에 둔다. overview 앵커, 기존 관련 자료 링크와 상세 목차의 위치 추적을 유지한다.

Project 데이터의 기존 problem 문자열은 introduction의 goal, background, features로 교체했다. 문제 해결 사례의 CaseStudy.problem은 별개이므로 유지한다. 세 프로젝트는 같은 소개 컴포넌트를 사용한다.

## 확인한 근거

### Ait

- C:/S15P11D202/README.md의 개발 배경 및 서비스 기능
- C:/S15P11D202/ai/README.md의 자료 기반 질문과 꼬리 질문 설명
- 현재 peerFeedback 컨트롤러와 프론트 연동을 확인한 자료 검토

모집, 연습, 평가와 소통이 나뉜다는 팀의 문제 정의를 사용했다. 이력서, 자기소개서와 GitHub 자료 기반 면접, 화상 스터디와 상호 평가, 스터디 운영과 채팅, 커뮤니티와 알림을 소개한다. 모든 기능을 김민범 개인이 구현했다고 쓰지 않는다. 과거 api-gaps 문서의 미구현 기록을 현재 코드보다 우선하지 않는다.

### ONEWORK

- 현재 포트폴리오 content.ts와 caseStudies.ts
- 저장소 루트의 프로젝트_정리_초안.md
- Notion [프로젝트 정리](https://app.notion.com/p/3eb5498d25a981c89b56e74deff1ea2e)의 ONEWORK 개요 및 기여 조사 기록

현재 기기에 C:/S15P21D202 체크아웃이 없어 원본 소스를 새로 검증하지는 않았다. 기존 자료에서 확인한 설비 진동 이상 감지, 공정 품질 원인 분석, 3D 트윈과 카메라 관제 범위를 사용했다. 배경은 프로젝트의 관제 요구로 설명하며 공장에 대한 별도 실태 조사나 고장 감소, 비용, 생산성 및 지연 수치를 추가하지 않는다. HTTPS 환경의 카메라 영상 연동은 미해결이라고 기능 설명에 명시한다.

### SteamFolder

- 사용자가 설명한 보유 게임 공유의 불편과 개인 프로젝트 목적
- C:/SteamFolder의 SteamController, FolderService, ShowcaseController, RankingController
- C:/SteamFolder-front의 DesktopCanvas와 랜딩 화면

Steam 계정 연동, 최대 5단계 폴더와 게임 배치, 쇼케이스 링크 공유, 좋아요와 랭킹을 소개한다. 목표는 현재 개발 중인 서비스로 표현한다. 로컬 개발 중이라는 기존 상태를 보존하며 외부 배포나 사용자 성과를 주장하지 않는다.

## 화면과 코드 확인

- 세 프로젝트를 PC 기본 크기와 320×740에서 열어 목표, 배경, 주요 기능 순서와 기능 네 개를 확인했다. SteamFolder는 768×1024에서도 확인했다.
- 각 상세의 목차 이름은 프로젝트 소개이며 overview 주소가 그대로 작동한다. 담당 구현 링크로 이동하면 해당 목차가 선택되는 것도 확인했다.
- ONEWORK는 소개의 카메라 기능에 HTTPS 영상 연동 미완료를 명시하고, SteamFolder는 기존 상세 상단의 로컬 개발 중 상태를 보존했다.
- 모바일의 소개 제목과 소제목이 비슷하게 커지는 상속을 바로잡았다. 소제목은 17px, 기능 이름과 본문은 15px이며 묶음 간격은 24px이다. PC에서는 소제목 18px, 본문 16px과 28px 묶음 간격을 쓴다.
- 모든 확인 화면에서 상세 스크롤 영역의 가로 넘침은 없다. ONEWORK는 모바일에서 네 기능과 미완료 상태까지 따로 읽어 확인했다.
- TypeScript 검사, Vite 프로덕션 빌드와 공백 검사를 통과했다. 레이아웃 탐지 결과는 빈 목록이다.
- 화면 기록은 portfolio/.impeccable/review/project-introductions에 저장했다.
- 상세 닫기를 누르면 dialog의 열린 상태가 해제되는 것을 확인했다. 작업 중 개발 서버의 열 업데이트가 기존 경로 데이터 객체를 유지하면서 새 introduction 필드가 없는 일시 오류가 기록됐으나, 새로고침 후 정상 로딩됐다. 새 탭에서 세 프로젝트를 다시 직접 열고 전환했을 때 각 네 기능이 표시되고 브라우저 오류와 경고는 없었다.
