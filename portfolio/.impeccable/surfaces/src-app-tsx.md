# 포트폴리오 화면 기준

## Direction contract — 2026-10-22 협업 공통 제목

홈 Experience 표면에서 두 활동을 h3 ‘협업’으로 묶고 h4 Git Flow와 스크럼 마스터를 좌우에 둔다. 기존 문장을 보존하며 공통 제목 24px, 소제목 18px, 가로 간격 48px과 제목 아래 24px 간격으로 위계를 만든다. 960px 이하에서는 기존 한 열 전환을 사용해 공통 제목과 두 활동을 DOM 순서대로 읽는다. 새 박스나 장식은 추가하지 않는다.

## Direction contract — 2026-10-22 검증 링크와 하단 탐색 제거

세 프로젝트의 검증별 커밋과 Notion 자료 링크, 상세 끝의 다른 프로젝트 탐색을 제거한다. 상단 저장소 아이콘과 닫기, 본문 목차와 직접 주소 및 기술 비교의 공식 문서 참조는 유지한다. Ait의 최신 50건 조건은 성능 표에 통합하며 두 긴 검증 주석을 제거한다. 게시글 목록 수치와 성능 개선 주장은 제외하고 채팅과 댓글 검증 설명으로 정리한다. 링크 자리의 빈 목록이나 여백을 남기지 않고 마지막 본문에서 자연스럽게 끝낸다. 기존 Read 모드의 팔레트, 글꼴과 읽기 폭을 보존한다.

## Direction contract — 2026-10-22 중복 개념도 제거

프로젝트 상세 Read 모드의 기존 회색과 차콜, 글꼴과 읽기 폭을 유지한다. Ait 기능 요약, ONEWORK 영상 전달 순서와 SteamFolder 폴더 예시의 큰 도식을 삭제한다. 기술 설명과 나의 역할에 있는 정보를 다시 박스에 넣지 않는다. ONEWORK의 FFmpeg 인코딩, MediaMTX 중계와 HTML 영상 창 재생은 본문 두 문장에 합친다. 기술 비교의 펼침과 성능 표, AI 피드백 순서, 상세 목차와 근거 링크는 유지한다. 이전 도식 표시 규칙의 해당 부분을 대체한다.

## Direction contract — 2026-10-20 상세 목차의 현재 항목

상세는 Read 모드다. 기존 좌측 목차와 작은 화면의 상단 두 열 목차를 보존하고 현재 읽는 항목 하나에 `aria-current="location"`을 적용한다. 이미 정의된 옅은 회색 배경과 차콜 650 굵기의 선택 상태를 사용한다. 본문의 실제 위치를 상세 창 내부에서 추적하며 스크롤에 따라 주소, 초점이나 읽는 위치를 변경하지 않는다. 목차 클릭과 세부 기록 직접 진입, 마지막 항목, 상세 펼침과 화면 크기 변경에도 표시가 맞아야 한다. 작은 화면의 링크 안쪽 여백은 기본, hover와 현재 상태에서 동일하게 유지한다.

## Direction contract — 2026-10-20 협업 경험 추가

기존 검증과 협업 두 행 및 회색과 차콜, 글꼴과 간격을 유지한다. 협업 제목은 ‘팀의 진행 상황을 함께 점검합니다’로 바꾸고 사용자에게 확인한 스크럼 마스터 역할, 매주 KPT 회고 진행과 번다운 차트 점검을 먼저 설명한다. Git Flow 제안과 가이드 공유는 다음 문단 및 기존 근거 링크로 유지한다. 오른쪽에는 역할, 주간 회고와 진행 점검을 기존 정의 목록과 같은 크기로 보여준다. 실제 회고 결과, 적용 프로젝트명과 번다운 수치를 추가로 추정하지 않는다.

## Direction contract — 2026-10-19 두 작업 방식과 처리 관계 정리

현재 작업 방식은 검증과 협업 두 행이다. nGrinder 전후 수치와 조건 및 개인 브랜치의 100건 동시 요청 검증을 같은 항목에 묶고, 실제 사용자 피드백 개선 사례는 배포 후 별도 근거가 생기면 추가한다. 미래 성과나 빈 항목은 표시하지 않는다. 화살표 정리에 대한 사용자 확인을 거쳐 처리 순서는 공유 ProcessSteps 번호 목록으로, 분류 결과와 기능 역할은 정의 목록으로 표현한다. Ait 기능을 순서로 바꾸지 않으며 SteamFolder 폴더 계층은 중첩 목록으로 유지한다. 전후 측정은 열 머리글로 구분하고 메일, 다른 프로젝트 및 맨 위 링크의 장식 화살표는 제거한다. 펼침 Chevron과 실제 새 탭 표시는 16px로 보존한다. 기존 사실, 수치, 조건과 미해결 범위는 유지한다.

## Direction contract — 2026-10-19 AI 검토 기준의 구분선 정리

사용자가 승인한 방향은 세 검토 기준의 설명을 항상 읽는 방식이다. 기존 회색과 차콜 및 두 글꼴을 보존하며 항목을 h4와 p로 구성한 텍스트 목록으로 표시한다. PC 세 열에서 820px 이하 한 열로 전환한다. 세 항목의 선과 화살표 및 첫 사례 위 선을 제거하고 AI 영역 시작선만 보존한다. 소개와 기준은 32px, 기준과 사례는 PC 56px 및 작은 화면 48px 간격으로 묶음을 구분한다. 원문 및 두 사례의 상세 펼침과 링크는 보존한다. 다섯 화면과 키보드, 상세 복귀 및 빌드 검증을 완료했고 별도 마감 검토는 ship이다.

## Direction contract — 2026-10-19 상세 창 잉여 공간

상세는 Read 모드다. 제목과 메타 정보 다음 목차와 본문을 읽는 순서 및 72ch 본문 길이를 보존한다. 본문 오른쪽에 남는 별도 공간을 없애기 위해 공통 모달 최대 폭을 1200px에서 960px로 줄인다. 960px 이하의 상단 목차 배치에서는 모달을 최대 704px로 맞추고 600px 이하의 기존 규칙을 보존한다. 세 프로젝트와 다섯 화면 크기, 목차와 닫기 및 초점 복귀를 검증했다. 빌드와 layout 검사 통과, 별도 마감 검토 ship.

## Direction contract — 2026-10-19 전체 첫 화면과 작업 방식 가독성

THESIS: 첫 소개에 한 화면을 할당하고 작업 방식의 설명과 근거를 순서대로 읽게 한다. 사용자가 작업 방식의 가로 행 세 개와 AI 활용까지 함께 정리하는 두 질문에 동의했다.

OWN-WORLD: 기존 밝은 회색과 차콜, Noto Sans KR 및 Manrope, 공통 중간 너비와 프로젝트 사진 전체 표시를 보존한다. 내용과 검증 수치 및 조건은 유지하고 글자와 그룹 구조만 정리한다.

STORY: 소개를 읽고 스크롤해 프로젝트와 작업 방식에 도달한다. 작업 방식은 왼쪽 설명과 오른쪽 근거, 근거 아래 링크로 읽는다. AI도 소개와 검토 기준 다음에 두 사례를 하나씩 읽고 도식 아래 상세를 펼친다.

FIRST VIEWPORT: 소개는 100svh에서 실제 헤더 흐름 기본 80px 및 600px 이하 72px를 뺀 최소 높이다. 짧은 화면은 내용을 자르지 않고 늘어난다. 작업 방식 행의 제목은 24px, 본문 18px, 조건과 코드 14px이며 모바일 제목 22px와 본문 16px다. 960px 이하 행 내부는 설명 다음 근거로 쌓는다. AI 사례는 820px 이하에서 설명 다음 도식으로 쌓는다.

FORM: 첫 소개 높이와 작업 방식 및 AI의 가독성을 다듬는 제한된 refinement다. 프로젝트와 다른 영역의 너비 및 상세 동작은 유지한다.

FINISH: 13개 화면과 펼침 및 근거 링크, 빌드와 실제 넘침을 확인하고 docs/design.md 및 sidecar와 검증 기록, 독립 마감 검토를 남긴다.

## Direction contract — 2026-10-19 낮은 단일 프로젝트 카드

최신 공통 너비 요청: 사용자가 다른 홈 영역을 기존 넓은 너비와 현재 프로젝트 너비의 중간으로 맞추고 프로젝트는 왼쪽, 가운데와 오른쪽 여백을 늘려 같은 너비로 맞추도록 요청했다. 모든 홈 container와 footer는 실제 기존 홈 너비와 compact 프로젝트 너비의 산술 평균을 공통 최대 너비로 사용한다. PC 1440px에서는 1010px, 1920px에서는 1170px, 2560px에서는 1250px다. 프로젝트는 flex와 space-evenly로 기존 개요 283.33px 및 사진 566.67px의 선호 폭을 유지하며 남는 폭을 세 여백에 고르게 나눈다. 820px 이하에서는 최대 606px 내부 열을 가운데 둔 단일 grid로 양쪽 여백을 늘린다. 휴대폰은 기존 너비와 배치를 유지한다. 사진 전체와 자연 비율 및 단일 상세 진입 동작은 유지한다. 이는 앞선 프로젝트 전용 900px/640px 폭 예외보다 우선한다.

THESIS: 개요와 사진을 하나의 낮은 카드로 이어 단일 상세 진입점으로 사용한다. 이 후속 요청은 앞선 두 개의 링크와 분리형 카드보다 우선한다.

OWN-WORLD: 기존 회색과 차콜, Noto Sans KR 및 Manrope, 실제 로고와 화면 원본을 유지한다. 내부 경계, 캡션과 원본 보기 링크를 제거하고 외곽 경계만 둔다. 사진 전체와 원본 비율 및 표시 크기를 보존하고 공통 너비와 내부 여백으로 균형을 맞춘다.

STORY: 로고와 개요, 옆 사진을 함께 읽고 어느 부분에서든 같은 상세 모달을 연다. 새 탭은 만들지 않는다.

FIRST VIEWPORT: 홈 소개와 프로젝트, 작업 방식, AI 사례, 소개 및 기술, 연락처와 footer는 같은 공통 폭과 좌우 기준선을 사용한다. 프로젝트 카드는 이 폭에 맞춰 늘리되 사진 자체는 키우거나 자르지 않고 좌우와 가운데의 여백을 늘린다. 820px 이하에서는 설명 아래에 사진을 두는 기존 순서를 유지한다.

FORM: 현재 디자인 안에서 홈의 공통 너비와 프로젝트 내부 여백을 조정한다. 문구와 상세 내용 및 기존 클릭 동작은 보존한다.

FINISH: 빌드와 묶음 화면 검증, 키보드와 전체 클릭 영역 확인, 문서 및 별도 마감 검토로 끝낸다.

## Direction contract — 2026-10-19 프로젝트별 화면 미리보기

THESIS: 프로젝트의 정체성과 실제 서비스 모습을 한 줄에서 함께 읽게 한다. 사용자가 확인한 왼쪽 카드와 오른쪽 큰 미리보기로 세 프로젝트를 세 줄에 배치한다.

OWN-WORLD: 밝은 회색 바탕, 차콜 글자, 기존 Noto Sans KR과 Manrope, 원본 로고 색과 카드 외곽선을 유지한다. 제공된 화면의 색과 내용을 바꾸거나 새 화면을 만들지 않는다.

STORY: 로고, 이름과 개요를 읽고 옆 화면을 확인한다. 왼쪽 카드는 기존 상세 모달을 열며 오른쪽은 원본 이미지를 새 탭에서 연다. 실제 서비스 링크와 담당 기능 화면은 나중에 보충한다.

FIRST VIEWPORT: 프로젝트 영역은 제목 아래에 카드 1열과 미리보기 2열 비중의 행을 세 개 쌓는다. Ait과 SteamFolder에는 랜딩페이지, ONEWORK에는 기존 관제 이미지를 사용한다. 820px 이하에서는 카드 다음 화면 순서로 쌓는다. 미리보기는 약 2:1 프레임 안에서 전체 비율을 보존한다.

FORM: 승인된 회색 디자인 안의 레이아웃 확장이다. 이전의 동일 너비 카드 세 열을 대체하며 다른 영역과 모달 동작은 보존한다. 새로운 컨셉 선택은 필요하지 않은 국소 변경이다.

FINISH: 빌드와 데스크톱, 중간 폭, 모바일 묶음 검증, 자산 출처 기록, 별도 마감 검토로 끝낸다. commit과 push는 요청받지 않았다.

홈: Experience. 프로젝트 상세 모달: Read. 채용 담당자와 기술 면접관이 본인 구현 범위·문제 해결 근거를 읽고 연락하는 흐름이다.
